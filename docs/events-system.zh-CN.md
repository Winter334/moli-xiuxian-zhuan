# 随机事件：形式与首批范围提案

更新：2026-09-27。
状态：用户认可形式方向，明确要求**留档即可，暂时先不做**。
本文保留设计构想，不继续细化、编码、配置事件内容或接入界面，不作为当前先天气运的实施依赖。
用户同时明确当前内容不足以支撑后天气运，因此后天气运整体后置。
下文与后天气运有关的例子仅作历史讨论留档，不是恢复事件开发时可直接启用的奖励方案。

## 1. 推荐形式

采用「自动发生的小插曲 + 可稍后选择的机缘」，少量重要内容以后延伸成短事件链。
世界里的事情会发生，玩家偶尔决定怎么参与；不把所有事情都变成一次必须点开的领奖。

| 形式 | 优点 | 对当前项目的取舍 |
| --- | --- | --- |
| 全部自动结算 | 适合挂机，回看成本低 | 适合小插曲；单独采用容易只剩随机资源加减 |
| 发生就弹窗、暂停直到选择 | 临场感强，容易表达紧急情节 | 不建议作为默认，离线时会中断养成，频繁回来确认变成必要操作 |
| 发现后保留，玩家回来再处理 | 保留选择，又能继续原活动 | 推荐为主要机缘形式；需要明确发生和选择是两个时点 |
| 独立探索棋盘、长任务树 | 可承载复杂分支与路线 | 暂不增加，会同时引入移动、任务管理和新的主要玩法 |

事件不只属于秘境，也可来自打坐、功法专修和既有成长节点。

## 2. 三种内容层次

### 2.1 小插曲：自动发生，结果直接生效

适合没有真实取舍、收益较小的事情，例如修习中悟通一处、沿途发现少量材料。
不弹强制对话，不放「领取」按钮，结果写入修行记录和离线摘要。
纯叙事见闻也可以没有物质奖励，不为每段文字附送属性。

例如「旧注新解」：专修当前功法时，忽然理解了旧注中的一句话，
自动获得少量该功法修习经验。遵循该功法上限，不增加其它功法经验，不等于免费升满。

首批不加入无预警的装备丢失、境界跌落或长期重伤，避免随机事件让已知安全的挂机突然失控。
这不是要求事件永远只有好事；明显损失和危险可放在玩家主动接受的选项里。

### 2.2 机缘：发现一件事，保留两三个有意义的选择

发生时只留下线索或约定，不扣资源、不代替玩家选择、不停掉普通挂机。
玩家查看一小段情境、各选项的明确投入与结果方向，再决定参与或离开。
机缘不是考试，选项不应普遍是「看起来正确的答案」与「纯吃亏的答案」。

**例一：青竹林的药草标记**

一名药户留下记录：林中一片灵草到了可采之时，也可留其根系养护。

| 选择 | 结果方向 | 取舍 |
| --- | --- | --- |
| 采收成熟灵草 | 获得一份当地药材 | 眼前制作资源 |
| 以已有灵材养护根系 | 消耗明确材料，获得本世「林息眷顾」 | 即时支出换取本世小幅生存优势 |
| 记下见闻，不再参与 | 不消耗、不奖励 | 可以明确结束，不强迫每件事都处理成收益 |

历史说明：这是当时对「林息眷顾」来源的形式示例；用户最新认为获取过易，
该后天气运投放方案已经撤回，表格仅保留讨论记录，不作为候选配置或默认奖励。
若已经持有该气运，不得再扣材料换取无效重复项；显示已有状态并禁用该交换。

**例二：旧矿中的残缺纹图**

在已清理的矿道里发现一片刻有导灵纹的旧板。
可以取走其中可用矿料，也可支付一份明确的辅助材料，将纹图整理成炼器经验。
两条路分别服务于眼前打造与生产成长，不要求先有高熟练度才给唯一正确选项。
这类即时研究不声称占用数小时，也不暗中增加第二条持续修炼活动。

事件有明确风险时，在选择前告知，例如可能损失的投入、是否会进入战斗。
不用虚构的精确胜率替代实际战斗，也不把故事文案当作已承诺的效果。

### 2.3 少量后续：此前的选择改变以后可能遇到什么

例如整理过残缺纹图，后续在修习或探索中可能发现相关器方线索。
不必马上连续弹出第二、第三步；记录一个有具体用途的经历条件，之后加入合适的事件池。

建议先做两三步以内的短链，允许独立结束，不预建长篇主线、阵营好感或任务大厅。
后续机缘也可以发现一个可主动挑战的地点，而不是直接把角色传送进战斗。
挑战使用共同战斗规则，占用本体主要活动，不与原挂机并行获利，不自动开始或自动续刷。
首批可先不配置事件战斗，待实际需要时补最小接入。

## 3. 怎样发生，才不像凭空抽奖

事件池按「正在做什么、在哪里、本世到哪一步、已有经历」筛选，再进行随机选择。

| 触发背景 | 适合发生的事 | 不采用的做法 |
| --- | --- | --- |
| 秘境历练 | 当地资源、遗迹、可再访地点、他人留下的消息 | 所有区域共用一张无条件事件表 |
| 打坐、专修 | 感悟、旧注理解、修习相关线索 | 打坐时无缘无故碰见远方商队 |
| 首次清剿、突破、熟练度节点 | 重要发现、后续事件的开放条件 | 关键进度本身是否生效也随机判一次 |
| 炼制与成长经历 | 相关工艺线索，后续可参与的交换 | 按点击次数抽奖，拆开批量制作就多得机会 |

随机事件不必只有“每杀一个敌人抽一次”。建议普通随机发生机会主要来自有效活动时间，
成长节点负责较少的一次性触发或解锁。这样不会把所有机缘效率都变成低阶怪击败速度竞赛。
战败或活动停止后不继续按挂机时间生事件，登录、刷新、切换页面不产生额外机会。

具体检查间隔、发生概率与权重以后配置。内容变多时优先分配同一发生频率下的事件权重，
不每加入一个条目就新增一份独立发生概率，导致通知和额外产出随条目数失控。
气运可以明确改善某类事件的候选资格或选项，不默认为一项幸运属性同时提高所有概率。

## 4. 与挂机、离线和轮回的关系

以下均为本轮形式提案，沿用已有的单一主要活动与跨世边界：

1. **普通挂机继续。** 发现机缘不强制暂停。查看和资源交换等不改变本体配置的操作可直接处理；
   获得影响战斗的气运、主动培养或进入挑战，应遵守已有脱战边界，不能利用事件在战斗中换装。
2. **本世内不催上线。** 待选机缘首批不设现实倒计时；轮回时结束，预览列出未处理项。
   文案采用可再访的地点、留存线索或交易约定，不写成有人一直等待当场救援。
3. **自动事件已经结算，选择事件尚未兑现。** 离线发现机缘，回来选择后才发生相应消耗和收益，
   不将新气运倒算进此前几小时的战斗。自动获得的效果则从实际发生时点开始生效。
4. **发生时确定机会，处理时核对支付。** 事件内容及奖励档次依据发生时的区域、进度固定；
   不因囤到更高境界而自动升级。选择时核对当前库存、已有气运和必要条件，不够就不扣费。
5. **少而有分量，不靠队列催操作。** 首批选择型模板建议每世至多出现一次，不设小容量满后
   就吞事件的收件箱。可重复自动事件可合并相同结果的摘要，实际收益仍逐次正确结算。
6. **经历与机会分开。** 本世待选实例、短链进度及事件气运随轮回结束；已读见闻和永久成就保留。
   历史读过某故事不替新世完成要求，本世获得的资源不成为跨世待领奖仓。
7. **不能随机卡住基础成长。** 关键突破物资与基础配方仍有稳定路径；事件可提供捷径、备选、
   有特色的额外内容，不把偶遇唯一事件当作全体玩家都必须等到的门槛。

不把「不要求在线抢答」误写为主动上线选择没有价值；早作决定可以早用收益，
但不在线不会因此自动浪费已发现机会，也不会额外获得一套更差的离线事件规则。
首批避免有限时长的随机增益，防止尚无临时状态规则就提前给出错误的持续时间承诺。

## 5. 最小系统与首批内容

建议先支持自动结算和二三选一两种形式，用少量现有场景验证职责，不先堆几十条文案。
一个小批次可以是两条自动插曲、四条选择机缘；数量只是内容草案，不是固定上线指标。
当时建议覆盖修习、探索、资源取舍及本世后天气运来源；目前这一首批安排不执行，
尤其不再要求事件首批必须带一个后天气运来源。短链同样留档。

每个事件定义只需有：触发背景、资格条件、频率与重复范围、短情境、选项及其成本/结果。
实例保存本世归属、发生时点、生成的具体内容、待处理或已完成状态。
结果复用已有的资源、修习、气运和解锁能力，不为每个故事另写一套成长规则。
首批结果若需要尚未实现的能力，应先标明依赖，不能只写一句文案就视为已有内容。

实现时要保证发生机会不依赖客户端轮询或一次离线结算被拆成几段；
同一实例只结算一次，资源扣除与奖励入账一起成功，重连和重复提交不重新随机。
以上是稳定结算要求，不要求现在编写模拟、跑全量统计或建立通用任务脚本语言。

## 6. 当前结论

本轮推荐的体验是：**平时修行会留下少量新发现，回来能作几次真正影响资源或本世成长的选择。**
用户认可方向但已明确暂停该主题，当前不再细化频率、首批模板或结果类型。
以后明确恢复时再接续，不因先天气运开发而自动带上事件系统或后天气运。

本轮仅记录形式建议与已有方案的认可状态，后果可控、可预测，未运行测试或数值模拟。
未编写事件运行代码、调整数值配置、接入旧前端或读写角色数据库。
