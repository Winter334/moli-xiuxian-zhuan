## 1. 最新工作方式

用户指出内容增加、随机性扩大后，逐条精确测算的成本过高，要求采用估算等更高效的方法，
并先系统梳理，再有目的地完善，结束想到哪里做哪里的推进方式。

- 先回答内容为什么存在、解决什么需求，再决定增加、调整或暂缓什么。
- 先明确玩家应感受到的成长变化，再用参考数据与估算支撑；“有数值增长”不等于“有提升感”。
- 参考原始境界、关口和资源关系已构成原型底座；当前先完善自己的世界与经历，
  再区分题材重设与原创规则改造，不强行继承旧地图、装备和境界倍率，也不叠加全部旧系统。
- 数值先看量级、相对关系和合理区间，不追求指定路线在某分某秒必定得到某件装备。
- 随机内容仍可估计期望与成本，但不把期望当作个人体验保证，也不按单个种子的好坏调平。
- 精确性保留在引擎结算与规则正确性上；设计估算不改成离线按旧面板粗算收益。
- 只有关键问题无法通过估算判断时，才考虑最少的针对性检查，遵守根目录最小测试规则。
  不将首小时、六小时、多种子、全构筑或长期模拟作为每次工作的默认交付门槛。

单一主要活动、在线离线同规则、战败停止、材料打造、制作可失败、
功法与武器混搭等已有设计仍是后续接入依据，不等于本轮开始删改其实现。
普通小幅越级不是某一流派专属；不保证所有精英、任意跨度或无人值守均可轻松通过。

具体倍率、价格、材料量、成功率曲线、熟练度上限与当前路线结果仍是工作参数或历史样本。
不把线框槽数、旧内容目录件数、现有代码上限当成设计必须维持的数量。

## 5. 估算怎样使用

每个主题只记录足够决策的假设和结论，不建立一套逐笔重放账本：

| 要判断的事 | 优先采用的估算 | 必须注明的边界 |
| --- | --- | --- |
| 材料供应 | 单次胜利期望产量约为各怪物遭遇占比乘掉率和数量的总和；再乘粗略有效击败速度 | 遭遇占比不是原始权重；速度包含休整或单独扣除，不能重复扣；战败停止不能算满时长产出 |
| 制作成本 | 成功率近似固定时，单件平均尝试成本约为一次成本除以成功率；再看失败一两次的资金压力 | 是期望而非保底；熟练升级改变概率时按区间或阶段估算，不固定用零熟练概率推全程 |
| 装备与丹药 | 同一成长档的普通品质参考面板，比较换装净变化、丹药边际收益与投入量级 | 丹药数量从估计的掉落/制作与预算推导，标明假设，不当作实际获得；不靠极品证明基础可用 |
| 战斗与续航 | 分别估输出、物法承伤、灵力净消耗与有限补给能支撑的场次 | 保留破防、爆发伤害、耗灵回退等阈值，不压成一个综合战力或用平均敌人证明全区安全 |
| 境界与洞府 | 修为需求相对有效收入、加速带来的大致节省、洞府相对战力投入的机会成本 | 只有实际打坐/专修时间获得对应加速；取材战斗不能同时计算洞府修炼收益 |
| 长时积累 | 用合理速率区间粗看资源和属性的增长量级 | 不把一小时速率外推为永久常数，也不据此承诺六小时连续存活 |

共用材料先分配用途：同一份不能同时打造、炼丹又出售；同区共同掉落不逐项累加完整刷取时间，
不同区域分开取材则需要计入相应时间。阶段性库存和熟练升级只在它们会改变结论时细分。

默认比较一个常见情况与一个偏不利情况，必要时补一个高投入情况；具体采用几个由问题决定，
不是每个流派、每件装备都必须做一套。偏不利情况是说明过的设计假设，不冒充统计分位数。
估计不确定时直接标注，例如“偏贵”“明显替代”“大约同档”“可能卡在破防阈值”，
不使用小数点后的精度制造可靠感。

若合理假设下结论相同，即可据此推进；若结论会反转，先找出影响最大的那一两个参数，
必要时只观察对应战斗或操作。资源守恒、重复发奖、随机结算、批量一致性等正确性问题
不能靠平衡估算替代，但也不因此默认跑全量测试。

## 6. 有目的的推进方式

系统盘点与首段结构保留为总体参照；用户已确认本轮按以下依赖顺序分批实现，
不要求等所有总体系统设计完成才编码，也不把工作数值写成最终平衡结果。
不将历史失败样本或某件饰品的问题自动设为下一轮第一项开发。
下表为此前实现顺序记录，被后续批次替代的项目已注明现行去向；当前处于正式UI重建阶段。

| 顺序 | 产出与完成依据 | 当前状态 |
| --- | --- | --- |
| 1. 熟练度与共用效果 | 新经验、逐级与阶段收益、专属丹方，以及本世经验和跨世记录的归属 | 已实现；经验按敌人境界与配方区分的口径沿用至今 |
| 2. 先天气运与幸运 | 抽取、选择、正式入世、实际效果、适用掉落幸运 | 已被新版轮回与气运替代，见[轮回与气运重设计](reincarnation-fate-rework.zh-CN.md) |
| 3. 筑基与挑战 | 首领、炼气挑战上限、材料、三种突破及天道成就共用权威结算 | 概率筑基与成就规则已退役，现为三丹必成，见[筑基改造](foundation-rework.zh-CN.md) |
| 4. 轮回贯通 | 预览与结算、保留与重置、开局能力、下一世重选及有限重修 | 已被新版轮回替代，见[轮回与气运重设计](reincarnation-fate-rework.zh-CN.md) |

每个实施主题保留一条简短记录即可：
“要解决什么 -> 本次包含/不包含什么 -> 依赖什么 -> 用什么判断已经足够”。
例如恢复主题应一起解释脱战恢复、有限持续丹和常见回血的分工，
而不是只追着一件饰品反复增减数值；这只是组织例子，不表示现在先实现恢复。

新想法放回对应主题和内容阶段，再判断是否影响当前目标。
未影响当前目标的想法保留待排，不直接插入开发；必要依赖可以调整顺序，但要说明原因。
完成后更新本表和有关专题，不再把全部历史路线输出复制到每份交接文档。
