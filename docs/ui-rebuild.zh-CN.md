# 正式 UI 重建

更新：2026-10-04。

## 1. 已确认方向

- 现有临时页面和过去的布局设计退役，从头组织新版前端。
- 先设计、试玩并调整 UI，再按用户当轮授权确定美术批次；不自动接旧图或扩大全量生成。
- 桌面和手机横屏共用宽屏结构，不制作竖屏手机版。移动端Activity自动请求并锁定横屏；
  普通浏览器、不支持或锁定失败时保留转向提示，具体边界见[移动端方向](#移动端方向)。
- 音乐可先临时使用原作 NekoRPG 资源。
- 本轮是表现与操作层改造，不重做内容、数值、轮回或保存规则。
- 用户不认可首稿，最新要求借鉴原作三块区域的职责，细节不照搬：
  左侧角色与快捷消耗品，中央完整系统视图，右侧可筛选日志。
  角色立绘要预留较大区域，可以切换详细属性与技能等级；详情使用页面级模态窗，
  不嵌在侧栏中。保留完整行囊，减少固定分栏和层层页签。
- 用户2026-10-01确认玩家形象不制作生成素材，后续玩家头像及名字使用Discord头像与昵称；
  此决定替代此前玩家立绘美术需求；Activity已接真实身份展示，用户反馈登录通过，
  见[Activity接入](discord-activity.zh-CN.md)。本机开发/预览的临时占位不代表实际Discord身份。

当前已接入三栏第二稿及本次游历/战斗修订。用户已认可同一画布分级展开，
并反馈调整节点连线、紧凑填充战斗卡、安全点再战及独立敌人图鉴。
具体视觉仍待用户体验调整，不宣称整版已认可或可发布。首稿不再保留为可切换布局。
用户后续要求重做行囊布局，网格方案已接入；最新按反馈补格内价值、常驻分类、
轮换排序与高品质强调，用户已认可本轮行囊调整。
随后要求类似方式改造炉鼎，统一目录与制作弹窗已接，用户后续已认可本轮炉鼎调整。
最新指定修行页；用户否定功法网格卡片，并指出未来功法效果不一定相同，
共同属性对照表也不适合。当前已撤回这两版，改为下述独立纵向条目，仍待用户体验确认。

## 2. 信息与操作

### 常驻部分

采用顶部地点与公共历法、左侧角色栏、中央系统页面、右侧日志。
低饱和炭灰为底，玉绿标记有效操作，金色表示灵石，暗朱表示气血和风险。
标题采用系统中文衬线字体，正文采用系统字体；不依赖外部字体网络请求。

- 中央顶部保留六个全局入口：游历、行囊、修行、炉鼎、履历、世界。
  重入轮回入口在履历页下方区块，开发控制台放顶部更多菜单，不挤入角色数据区。
- 左侧常驻境界、气血、修为、战力与可用灵石；立绘区域与属性/技能列表二选一。
  Activity登录后改为Discord头像、全局显示名及用户名；本机开发/预览保留立绘占位，
  不再为此制作玩家立绘，实际登录与展示待用户测试，细节见[Activity接入](discord-activity.zh-CN.md)。
  属性、技能、气运、药效和灵髓详情均通过挂在`document.body`的原生模态窗展开。
- 技能详情按当前等级展示已有非零加成，常驻里程碑、对应武器类型生效及功法运转收益
  分开列出，并标记生效状态；保留功法代价，不把单项来源当作完整角色面板。
  该技能提供的战斗/清理修为及技能熟练倍率、两类精通对已取得关联技能的当前倍率同步展示，
  复用原属性来源、全经验与精通公式；星解盘另列领域专属倍率，不与全经验合并计数。
  无对应加成时不铺空区块，也不提前揭示未取得关联技能。
- 左侧底部为可滚动消耗品卡片列表，列出持有且有使用入口的全部物品，显示真实图标、名称和数量。
  每项右侧提供1个、10个、全部三种操作，沿用境界资格和原单次批量上限；
  不足10个时禁用10个，持有数量超过单次上限时禁用全部，不偷偷截取或循环提交。
  用尽移出列表，操作中防止重复提交；四格配置及其UI偏好读写退役，不复制行囊详情或交易功能。
- 右侧保留真实日志，按事件分类及关键词组合筛选，可切换跟随最新或回到末尾。
  设置弹窗提供最近记录展示条数50/100/200三档，只影响显示，不改核心保存；
  偏好与分类开关同键`moli.ui.log-settings.v1`保存，内存预览不读写该键。
  滚动阅读不暂停游戏；浏览其它页面也不打断正在执行的活动。
- 世界频道使用中央独立主导航页，右栏不承载聊天；地点页提供同地道友与
  查看公开资料入口，社交范围及实施见[社交系统](social-system.zh-CN.md)。
- 云端保存、音乐及全屏在顶部工具区。左侧底部当前活动可返回中央当地页面。
  手机Activity启动时顶部工具组向左留出64px，避开Discord右上角退出按钮；
  普通网页及桌面Activity位置不变，设备的`safe-area-inset`仍沿用。
  更多菜单提供隐私与条款，政策范围见[Activity接入](discord-activity.zh-CN.md#第三批身份名录与独立联调)。
- 系统商店、商盟寄售、璇玑阁由当前地点提供入口，不拆成新的地图节点。
- 交易待确认、轮回冻结、保存失败与冲突仍由原客户端状态驱动，保留核对入口，
  不因换界面而忽略预留资产或自动解除冻结。

| 修行 | 已解锁功法为独立纵向条目，呈现自身风味、效果/代价、熟练及直接操作，不做网格或共同属性对照表；只展示已掌握神通，详情使用页面级弹窗 |

| 轮回 | 入口在履历页；重置/保留说明、损失确认和原跨世提交，未增加门槛或成长奖励 |

本次覆盖此前选点预览/确认前往的界面：普通点击具体地点即发出到达命令，

快捷入口不改变安全落点、不回满气血、不绕过活动资格；本次会话最近战区在任何安全点
均可再探，已完成挑战除外；刷新后仍可通过山河图重返。
战败落点及本批调整见[调息专题](meditation-rework.zh-CN.md#战败返回调息安全点)。

### 行囊改造

- 桌面将八个配装位压为单排，窄横屏允许横向浏览；空槽可点击，直接筛选对应部位的袋内器物。
  配装可手动展开/收起，矮横屏默认收起以留出物品首屏；不制作独立竖屏布局。
- 袋内采用自适应网格，直接展示名称、数量或品质及回收单价；单价以灵石图标和每份/件标注，
  不显示整叠总价或购入价，悬停可看精确单价。已穿戴物只列在上方，
  卸下后回到袋内，装备后从袋内移入配装栏。只是展示分组，不改变实例归属或容量计算。
- 搜索、类别与装备部位组合筛选；类别常驻一排按钮，选中器物时直接显示部位按钮，
  不用下拉框。较窄中央区域隐藏类别数量但保留全部类别，数量仍可由悬停提示查看。
  排序为固定宽度按钮，逐次循环类别、名称、品质优先、价值优先；后两项由高到低，
  悬停提示下一种方式，改变排序不清除筛选。
  行囊与炉鼎排序分别由主界面持有，退出页面不重置，刷新或重新打开沿用本机
  `moli.ui.sort-settings.v1`偏好；无效值分别回到原默认，存储不可用不阻断当前界面。
  内存预览只在本次页面会话中保留，不读取或写入该偏好键；搜索、分类与其它筛选不随此批保存。
  数量与价格沿用精确数值格式化；排序不改库存、不新增“整理存档”命令，不虚构格数上限。
  工具区随中央页面滚动置顶，清除筛选与空结果状态保留；不另设永久详情列或层层标签页。
- 实例物品按既有`rarityMultiplier`品质分段显示颜色，较高品质采用更鲜明的边框、名称、
  图标及数字徽记，网格、当前配装和详情保持一致；保留实际品质数字，不只靠颜色区分。
  这只是视觉分段，不新增命名品阶、不改装备或炼材的属性/价格公式，也不为无品质的堆叠物伪造品质。
- 物品详情仍为页面级模态窗，名称、风味、用途、品质/编号和回收单价保留；
  候选器物将当前/所选属性逐项对齐，补齐中性值，区分固定加成与乘算并标出增减。
  直接使用现有View提供的来源加成，不将器物差异冒充完整角色属性或战力变化。
- 使用数量、装备/替换、卸下及更换入口固定在弹窗底部，长详情独立滚动；
  保留使用资格、批量上限、忙碌禁用及失败提示。商店购售流程仍在当地，不增加远程出售。
- 共用`Dialog`只增加可选底部操作区，原有弹窗无该参数时布局不变；
  加成文字格式化在`common.tsx`共用，保持原有百分比与乘算口径。未改核心规则、存档或版本。

### 商店售出操作

- 系统商店售出列表的堆叠物品直接提供1个、10个和全部按钮，图标、数量、单价及详情入口保留，
  悬停显示本次所得灵石；全部仅指对应一种物品，不出售整个行囊。
- 不足10个禁用10个；沿用单次10000个上限，超出时禁用全部并提示，不截取为部分数量或循环提交。
  命令提交期间禁用交易按钮并防重复提交，失败提示保留；购买与详情中的自定义数量仍走原交易入口。
- 器物与精炼器料可逐件交易，也可勾选后批量售出；支持名称搜索、器物/炼材筛选、
  全选当前筛选结果及清空选择，跨筛选保留已选项，确认窗列出全部已选项、品质、编号及合计灵石。
  已穿戴者不能勾选，也不进入全选；失效选择随库存更新移除，确认清单变化时须重新选择。
- 批量使用一条`sell-instances`命令（最多1000件），先核对重复、库存及穿戴状态，
  再复用原逐实例交易的精确价格、商店归属和履历记录，整批只保存一次。
  任一项不可售则整批拒绝；本地保存失败不发布售出结果，不增加远程出售或自动清理。

### 钓鱼显示与检查点

- 钓鱼恢复每秒角色结算/本地保存，按下与松开仍先推进至实际输入时刻、立即结算保存，
  不再为每个30毫秒运动步执行整角色校验、序列化与全界面重建；其它活动调度不随本批改变。
- 钓鱼面板用`requestAnimationFrame`独立投影当前鱼与竿的位置、收鱼进度，
  复用原`advanceFishing`的30毫秒精确规则和当前随机状态，位置使用`transform`。
  投影不结算物品或熟练、不抽下一条鱼，终点等待真实已保存检查点；暂停及长帧间隔不补播。
  鼠标/触屏捕获与键盘释放保留，重复松开事件合并；内存预览同样先结算输入前的时间。
- 不改变[灵鱼与钓鱼规则](qixia-to-fallen-ark-content.zh-CN.md#灵鱼钓鱼与湖心器物)中的
  等待、强度、运动、成败、熟练和收益，不改存档字段或保存版本。

### 炉鼎改造

- 普通炼制、精炼、兵刃合炼和防具升炼统一为成品导向的配方网格，不再通过下拉框切换几套页面。
  常驻类别为全部、补给、筑基丹、灵髓、炼材、器物、兵刃、升炼；沿用已有完整目录，不改开放规则。
- 默认只列材料齐全的配方，“显示全部”勾选后包含缺料项；清除筛选回到默认齐料目录。
  保留搜索，排序单键循环齐料优先、名称、成功率、参考价值；后两项从高到低。
  排序按[行囊偏好边界](#行囊改造)独立保存，清除配方筛选不清除排序选择。
  普通配方直接使用View的成功率与可供炉数，合炼/升炼按未穿戴可用实例计算可供组数，
  材料齐备不等于当前活动允许开炉，也不表示不同配方可以同时消费同一份材料。
- 网格显示名称、难度或制作路径、当前成功率、每次成功产量、回收价值和材料状态。
  固定成品使用现有回收公式，品质浮动成品只显示品质100参考价，完整口径放悬停与详情，
  不预先抽品质或保证成品价值。实际产量仍由成功判定和已有额外一批效果结算。
- 配方详情使用页面级模态窗，关闭保留目录筛选和浏览位置；成功率、持有量和本批用料优先呈现，
  风味与参考价随后。炉数和开炉按钮固定底部，材料消耗随炉数更新；不足、忙碌、战斗中不能提交，
  调息中提交会自然结束调息，规则与检查见[调息行动切换](meditation-rework.zh-CN.md#行动自然打断调息)。
  保留失败耗材提示和额外一批概率，不把接受命令的“已结算”提示写成炼制必成。
- 普通炼制及精炼配方的卡片、详情底部提供1炉/10炉/全部直接操作，自定义炉数保留；
  全部按该配方最短缺材料计算，不足10炉禁用10炉，真实可供炉数超过单次10000炉时禁用全部，
  不截取部分或循环提交。复用现有命令与防重复提交，数量表示尝试炉数而非保证成品数；
  卡片操作反馈直接显示在目录下方，合炼/升炼不自动选择或连续消费实例。
- 装备成品详情在用料前展示基础属性及既有特性，沿用共用装备来源与属性格式化，
  同时呈现正面收益、负面代价和乘算。品质浮动装备明确标注品质100参考及实际属性随品质变化，
  固定属性器物单独标注；不预抽品质，不将基础属性冒充角色实际增益或战力变化。
- 消耗品成品详情在用料前展示每份使用效果，包含恢复/增益、持续时间、副作用、
  同效续时、适用境界及筑基丹/灵髓原有作用；未持有成品也可查看。
