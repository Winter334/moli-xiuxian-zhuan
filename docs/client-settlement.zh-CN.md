# 客户端结算与低频云存档

更新：2026-10-02。此决定覆盖此前服务端逐秒结算与每秒同步的实现要求。

## 已确认方向

- 面向 Discord 社群的非盈利小游戏，以客户端运行 RPG 主流程；不为盈利或竞技级防作弊保留高频服务端结算。
- 本地自动保存作为运行缓存，正常进度继续低频上传；联机以已核对的云档为唯一接续基准。
  不提供本地分叉覆盖云端或玩家存档导出，未同步本地档经明确确认才能由云档替换。
- 基础反作弊即可，接受有意修改程序的人仍能伪造部分有效数据。
- 继续不补算关闭页面后的战斗；安全地点歇息/安睡的离线规则本轮不取消。
- 当前线上存档必须兼容或显式迁移，不清库、不覆盖无关进度；
  上线前退役的原型不自动接回，原玩法与布局不恢复。

## 已实现

| 部分 | 当前行为 |
| --- | --- |
| 客户端规则 | `src/game-client.ts` 直接调用原有 `core/prototype` 精确规则，不做另一套简化伤害、经验或掉落公式 |
| 本地推进 | 每秒安排一次本地结算，操作前推进至本地检查点；命令成功先本地保存，再发布结果 |
| 存档 | `src/local-save.ts` 使用独立 localStorage 键、严格格式和 SHA-256 摘要；每次本地推进/操作落盘，不依赖退出事件 |
| 多页 | Web Locks 限制同一存储空间只有一个活动页面；写入前再核对原始值，拒绝陈旧页面覆盖 |
| 时钟 | 连续运行按 `performance.now()` 的单调时钟推进，不用系统时间跳变补在线战斗 |
| 暂停续接 | 启动时战斗、训练和采矿整段暂停；运行间隔超过5秒也暂停该段，保留敌群/活动、气血、随机状态、历法与剩余计时 |
| 安全地点 | 未处于训练或采矿时，启动依据本地保存时间补算歇息/安睡，包括恢复、药效、养息经验与历法；分块保存并让出事件循环 |
| 云端 | `server/client/` 只创建初始角色、读取快照和校验/接收上传；没有逐秒战斗推进、奖励重放或后台挂机任务 |
| 低频备份 | 每60–75秒错峰尝试上传有变化的存档，也可手动上传；收到的只是小型回执，不重发地图、配方与完整视图 |
| 网络故障 | 本地继续运行；上传内容和请求编号先保存，结果不明时重试同一份请求，刷新后仍可续接 |
| 联机入口 | Activity每次启动核对云档；只有完全相同的缓存或明确采用的云档能够开启联机，未同步缓存不自动上传 |
| 冲突 | 按云端版本条件更新；冲突停止在线操作，只提供明确采用云端的恢复入口，不重新绑定本地分叉的上传基线 |
| PVP检查点 | 开战前本地保存并冻结，服务器结算后应用匹配回执；待确认不上传、不接受新资产操作，详见[PVP专题](pvp-system.zh-CN.md#单方推演与结算) |

网络断开不等于页面停止运行：已打开且有本地存档的客户端可以继续游玩。
仍运行本地计时器的后台标签也可继续；浏览器挂起或节流超过5秒则暂停战斗/训练/采矿，不补发整段收益。
训练在云麓驿批次接入，只在线给身法/体魄熟练度，
不是新增离线境界修炼。停止训练后安全地点的离线歇息规则不变。
采矿在石炉坞批次接入，完整周期才判物品并给熟练度，
未完成周期可保存续接；关闭期间保留已完成秒脉冲，不补物品或熟练度。
石炉坞床铺离线恢复可用，基础养息经验2/秒；草屋仍为1/秒，历法和恢复公式不变。
这不是 PWA 离线安装实现；关闭页面后能否无网络重新打开应用资源，本批没有提供保证。

## 工作默认

- 本地运行间隔1秒，连续计时间隔上限5000毫秒；这是调度容差，不是额外离线战斗额度。
- 云备份每60秒加0–15秒错峰偏移；每次失败后的下一次尝试仍按这个低频周期安排。
- 服务端每角色新上传至少间隔10秒；相同请求的回执重放不再次写库。
- HTTP上传上限256 KiB；当前最多1000个装备/部件实例（含货摊），单项库存或钱币不超过 `10^12`。
  这是首段原型接收边界，不是未来经济参数或本轮新增奖励上限设计。
- 同一浏览器存储空间只有一个活动客户端。跨设备不自动合并分叉存档。
- 无本地存档时首次连接服务，创建独立角色或取回已认证身份对应的客户端云档。
  Activity有本地缓存时也在启动读取云档，比较经共用规则解析的完整保存内容，
  不以本地修订号或自报“已上传”为凭证，JSON对象键顺序不同不构成进度差异。
  相同缓存按服务端时钟接续允许的离线休整；不同、读取失败或存在待确认事务时，
  本地仍保留，联机与新在线资产操作关闭。开发本机与内存预览不接入真实联机。
- 本地损坏、格式不兼容、存储不可用、身份不符或云端冲突均明确报告，不自动清除/重置角色。
  永久性云端拒绝后停上传，但本地仍可玩；已接下节的存档核对与恢复入口。
- 云端只保留最新快照及最后一次上传回执。云备份失败期间的进度只在本地，
  不能保证另一设备已有最新进度，也不能把关闭页面时的请求当可靠保存方式。

这些是本批技术工作默认，用户没有逐项确认频率或限制数值。

## 存档核对与恢复

顶部更多菜单提供“存档管理”，保存问题提示旁也可进入。核对时只读取当前认证账号的
`GET /api/client/save`，不会匿名建角、合并分支或改写云档；显示本地保存时间、
云端角色的进度时间（不是服务器接收时间）、世次、境界、修为与地点。
新设备没有本地档时仍沿用首次取回流程，不要求先手动恢复。

- 采用云端：须勾选替换确认；再次核对身份、版本、规则及云端修订，
  修订变化时要求重新查看和确认。替换当前设备的全部本地进度，不将未上传进度合入云档。
  恢复后仍按既有离线规则暂停战斗/训练/采矿，保留允许的安全地点休整。
- 云端落后：明确展示本地与云端进度，确认采用仍会舍弃云端检查点之后的未上传进度；
  不自动择新、合并或先上传本地来绕过确认。取消只保留本地游玩，不能进入同地名单、
  世界频道、寄售及其它新的联机操作。正常已核对会话内的本地推进与低频上传保持，
  上传结果不明期间停止联机，原请求重试获得确认后恢复；重开仍须重新核对云档。
- 原件保留：采用云端前先把当前原始字符串保存在同一账号键的`:recovery`副键，
  再写主键；仅保留最近一份，不能保存副本或发现另一写者时不替换主键。
  损坏/旧格式原件也保留；不提供玩家导出、导入或恢复本地副本的入口。
  这是设备上的恢复副本，与下文三档数据库备份独立。
- 损坏与身份：本地摘要、格式或版本不匹配时停止推进，只有明确操作才可用已验证云档替换。
  存储不可用、锁占用或身份不符仍先重试/重新登录，不能借恢复绕过另一账号或页面的保护。
- 待确认事务：核对界面只查原请求回执；未知或不匹配时不丢弃预留/冻结状态。
  匹配的已结算回执允许采用随后读取的云档；也可手动核对原交易/轮回请求，
  在线操作停止或云档来源未确认后，只允许这类原请求的手动核对，
  不恢复自动重试或允许新交易；未知结果不解除预留。
  PVP也须先取得匹配的结束回执，云端仍有活跃会话时不能替换；
  本地格式4兼容默认空的`pendingPvp`，云档与资产修订屏障见[PVP断线规则](pvp-system.zh-CN.md#工作默认与断线)。
- 核对及采用期间暂缓推进和新命令；检查结束按离线暂停规则衔接该段时间，
  不将网络等待变成战斗收益。普通浏览弹窗不持续暂停本地游玩。

## 基础防护

- 本地摘要能发现直接修改 JSON 或存储损坏；没有在前端藏密钥，也不声称摘要防得住主动重算。
- 本机开发上传身份取自 HttpOnly Cookie；Activity取自核实Discord账号后签发的短期Bearer会话，
  细节见[Activity接入](discord-activity.zh-CN.md)。身份必须与请求中的角色 ID 一致，拒绝替别人提交存档。
- 严格检查结构、版本、合法内容 ID、装备槽、敌群、属性与技能派生结果等原有规则一致性。
- 检查角色时钟不得显著超前、累计游玩时长不能超出服务端可解释的时间范围；
  境界/修为、技能、灵髓和已清组数不得回退。正常上传延迟不算加速。
- 限制上传大小、频率及基础数量；并发版本检查和请求摘要防止重复提交、旧版本覆盖与编号混用。
- 不验证完整资源来源，不重放每次战斗/掉落，不保证伪造的合理数量会被发现。
  未来排行榜不应把这套校验描述为严格公平成绩；交易、奖励和共享经济届时单独确定可信边界。

### 云存档键顺序校验修复

2026-10-02修复功法云档读取的`Character stats are not settled`误判：
PostgreSQL `jsonb`重排`statPolarity`对象键后，原字符串比较会把相同属性标记判为不同，
导致读取500及后续上传422。共用解析层现对收益/代价标记使用固定键顺序，
保留合法字段、值及派生属性校验，不改变数值、保存版本或数据库内容。
新增两门功法的对象键重排、读取不改档、连续上传及错误标记拒绝契约用例；
9项云存档服务用例和类型检查通过。用户提供的原始快照在内存中直接读取及再次上传通过，
属性值与原件均未修改；两门功法的修复前后正常上传请求摘要一致。
此前422产生的暂停上传标记会保存在本地，重开不自动解除。
后续云端唯一联机基准已移除“采用本地”的恢复方式；部署时应先修复正常上传，
已有未上传原件继续保留，不自动覆盖；玩家明确采用云端会舍弃这部分未上传进度。
真实玩家快照不纳入仓库或长期测试夹具，VPS同步部署及线上复测待进行。

## 数据与启动

### 三档数据库备份

用户确认上线后定期备份，保存在同一VPS的独立持久卷`activity_backups`，
与数据库卷、应用镜像及公开网页分离；最多保留三份完整归档：
更新前`update.tar`、4小时`quick.tar`、每日`daily.tar`。
快速档北京时间00/04/08/12/16/20点所在时间桶执行；日档每日05:00换档。
首次启动补建缺失档，服务中断后只备份恢复运行时的状态，不补造过去快照。

`deploy/activity-backup.sh`使用PostgreSQL17的事务一致性`pg_dump`，
包括账号、已上传角色、交易/回执、聊天及禁言表，不包括未上传本地进度或素材。
文件仅运维可读；归档内有数据库dump、SHA-256、目录清单、时间、
数据库迁移校验和、目标代码修订及最近成功部署的代码修订
（首次接入前旧代码修订可能未知，不能把目标修订当作备份对应的旧代码）。
新归档生成及基本读取检查成功后原子替换对应档，失败保留旧件；
三档独立、不按所有文件的时间统一淘汰，定时服务不触碰更新前档。

部署入口先构建、等待数据库、完成更新前备份，再启动可运行迁移的新服务。
失败更新的重试复用最初更新前副本，即使修复提交变动也不覆盖；
健康检查成功后解除本轮保护，下一轮更新才能换档，不自动回滚数据库。
未完成更新的保护标记核对归档摘要；归档缺失或不一致时停止更新，须运维检查处理。
已知异常时创建卷内`PAUSED`文件，停止各档轮换；解决并确认后才移除。
调度元数据和未完成临时文件不是额外完整备份；备份任务以文件锁互斥。
执行步骤与暂停命令见[部署更新](discord-activity.zh-CN.md#更新与验收)。

同机备份不能防整机/磁盘损坏，日档也不保证包含一天前的健康数据，
备份成功不等于每条玩家数据均已验证。恢复先解包、验SHA-256并在隔离数据库
读取恢复，核对代码/迁移版本和问题范围；保留当前线上原件，
不得默认回滚整个线上库或单独倒回交易资产。
有效删除请求也需处理备份中的相关资料，恢复时不能重新引入已确认删除的数据。
本地与云端进度分叉仍按原存档核对处理，不清除本地档来掩盖冲突。
