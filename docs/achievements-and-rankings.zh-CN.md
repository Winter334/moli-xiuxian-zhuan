# 成就记录与璇玑阁榜单

日期：2026-09-29。状态：用户已认可首版方案，履历、常态战力、开发四榜及当地临时入口已接入。
正式账号/道号及具体成就条目、积分、奖励仍未接入；本次未操作实际角色或数据库。
前置：地图基础规则和地点整理已收尾；本稿不恢复退役成就、旧天榜或旧奖励。

## 1. 已确认方向

- 下一项原创功能选择成就系统与排行榜，先做相对简单的内容。
- 成就尚无具体条目，先做好数据记录，方便后续增加成就。
- 排行榜采用角色数据直接排序，当前不做天梯；现有开放境界不足以支撑当前就做天梯。
  这是当前阶段的选择，不是永久否定以后增加天梯。
- 挑选重要数据上榜，并设计一个战力指标用于战力榜。
- 璇玑阁是另一个类似四海商盟的世界级巨无霸组织，拥有遍布世界的情报网络，
  各大人类聚集地都能看见它编制的榜单。

## 2. 实施前的代码依据

- 角色已有境界、当前修为、根基、灵髓成长、技能/功法熟练、神通掌握、炉阶、
  各战区累计清组数等状态；见 `core/prototype/character-state.ts`。
  这些可以直接判断状态型成就，不必再保存一套相同的计数。
- `clearedGroups` 记录清组，不等于逐类敌人击杀；角色近况日志只保留最近80条，
  不能把日志或当前库存当成完整生涯记录。
- 战斗和制作等收益在客户端结算，云备份目前每60秒尝试上传，服务端已有身份、
  上传幂等、版本冲突、计时与部分进度一致性检查，未重放每场战斗。
  见 `shared/client-save.ts` 与 `server/client/service.ts`。
- 当前云端仅有开发身份与角色存档，没有正式道号、公开榜单或Discord正式账号接入；
  不能把现在的本机角色目录当成已经具备正式公开排名资格。
- 现有属性包含攻防敏血、攻速、暴击、普攻倍率、固定/比例回复。
  敌人有破防门槛与多种特殊能力，单个战力值不能替代配装、命中及完整遭遇比较。

## 3. 成就先记录经历

首版增加一份角色履历，不做空成就列表、名称、积分或奖励。
目标是保存以后无法从当前状态倒推的事实，不把每次行动都保存为永久事件流水。

| 类别 | 新增记录 | 已有数据的复用 |
| --- | --- | --- |
| 历练 | 按敌人ID累计击败数量，累计战败/主动撤退次数 | 各区清组数、首清与挑战完成资格继续取原进度 |
| 制作 | 按配方记录尝试次数、成功次数、实际产量；自制器物按成品记录最高品质；装配/升炼也计入对应制作来源 | 炉阶与炼制熟练直接使用角色现状 |
| 采集与用物 | 按矿点记录采集周期和成功次数，按物品记录实际采得/消耗数量 | 灵髓属性、化悟及现存物品不重复保存 |
| 交易 | 累计购入支出、累计售出收入分别记录 | 当前灵石余额仍取角色现值 |
| 重要经历 | 首次到访地点、首次清区、首次达到境界，记录首次时间及当时境界；筑基根基沿用已有字段 | 功法/神通掌握直接使用已有记录 |

工作口径：

- 在动作真实结算时记账，和对应角色存档一起保存；拒绝的命令不计数。
  批量炼制10次就记10次尝试，成功炉数与实际成品数量分别记录，不把点击一次当一次炼制。
- 采得、制作、购买与使用分开记录，不把一件物品反复买卖当成反复自制或采获。
  浏览地图不计到访；真正到达或快捷探索才计。开发测试跳过不伪造正式经历。
- 只记首条里程碑和累计/最高值，不永久保存逐次战斗、逐次买卖或每秒记录。
  时间是角色履历资料，不用个人加速历法判断公共排名或最速竞争。
- 后续成就以“已有角色状态或履历满足条件”判断。能够由已保存事实判断的成就可回溯，
  未记录的历史细节不能补造，例如特定配装下无伤通关，须先增加对应记录再开放该成就。
- 不从旧库存猜累计产量，不从截断日志恢复历史。正式实施新增保存结构时按项目规则说明不兼容，
  不自动迁移旧存档。本次新增必填履历并升级结构，未处置实际角色数据。

## 4. 首版榜单

先用同一份公开榜单供各聚集地展示，不另外建镇榜、地域榜、赛季榜或天梯。
只展示荣誉排名，无排名奖励、每日领取、赛季重置或额外属性收益。
这些是本版取舍，不限制以后根据玩法需要增加。

| 榜单 | 排序口径 | 玩家价值与局限 |
| --- | --- | --- |
| 修为榜 | 先境界，再同境界的当前修为 | 展示修行进度；突破扣修为不会排到低境界之后，不按当前修为余额单独排序 |
| 战力榜 | 最新上传配装的常态战力评分 | 展示当前构筑投入，不保存历史最高配装霸榜，也不代表对所有敌人的实战胜率 |
| 炼制榜 | 炼制熟练等级，再等级内进度 | 给制作型玩家一个独立比较维度，不用容易靠低级配方刷大的成品件数排名 |
| 灵石榜 | 当前持有的灵石余额 | 简单展示持有财富，不叫总资产，不估价全部装备与库存；花钱后名次下降是这一指标的自然结果 |

首版工作默认：每榜前50名及自己的名次，同指标完全相同者并列。
公共信息只展示道号、境界、该榜指标和更新时间，不公布行囊、完整配装或当前位置，
也不借榜单泄露尚未开放的地点。
不优先做击杀总量榜和在线时长榜，避免把反复清低级区、单纯挂着页面变成主要竞争目标。

### 常态战力计算

战力只作可解释的面板估评分，不改变任何实际战斗规则，不作区域准入或必胜判断。
先解决统计口径，再采用一套简单公式，不为排名跑多场对战或完整通关模拟。

**纳入**：境界与根基、灵髓、熟练、当前已装备器物、当前运转功法和神通。
**排除**：丹药/食物等限时效果、当前剩余气血、休整回血，以及巡枢残印等阶段援助。
装备本身的负面属性与持续扣血仍计入，不能只取好处；已纳入属性的境界/根基不再额外加分。
未装备的库存器物、尚未运转的能力不凭拥有加分。

已认可并接入的首版公式，版本 `normal-power-1`：

```text
暴击期望系数 = 1 + 暴击率 × (暴击倍率 - 1)
攻势分 = 攻击 × 攻速 × 普攻倍率 × 暴击期望系数
持续回复 = 固定气血回复 + 气血上限 × 比例气血回复
续航折算气血 = max(0, 气血上限 + 10 × 持续回复)
战力 = floor(攻势分 + 防御 + 敏捷 + 续航折算气血 / 50)
```

除以50参照当前灵髓成长中气血相对攻防敏的计量关系，不代表50点气血在所有战斗中
恒等于1点攻击；10秒只是有限回复估值窗口，不是预计战斗长度或恢复上限。
攻速、普攻倍率和暴击进入攻势分，可避免只看攻击时严重忽略轻重武器差异；
回复有限计入，负回复扣减，避免把持续恢复当成无限有效气血。
加权值已完成第6节的少量静态配装对照，未做完整平衡验证，后续可据明确问题调整。
该公式没有模拟具体对手的防御、命中差距和特殊机制，因此评分高不等于一定打赢。
本次只做少量典型配装的静态算术对照，不进行逐秒模拟。
以后调整公式时以同一评分版本重算全部榜单，不能混用旧分与新分比较。

## 5. 璇玑阁与接入边界

组织名称、体量、遍布世界的情报网络和聚集地榜单均为用户已确认设定。
已认可的首版投放：

- 以四海商盟承接商贸，璇玑阁承接情报和公开榜单，两者职责不同，不合并为商会附属功能。
- 榜单放在聚集地的当地功能中，不为查看榜单增加独立地图节点或额外赶路步骤。
  首版在石桥镇、望川外埠/西市、千渠埠开放，同地看到同一份榜单。
  槐溪村仍属对外封闭的起步村，不补璇玑阁驻点；山院遗迹与歇脚点不因安全就默认有榜单。
- 首版排名对象是接入的玩家角色，不把榜首炼气或筑基玩家写成整个世界最高境界修士。
  “璇玑阁收录修士的名录”可作为呈现，不额外创造当前无从验证的全知情报能力。
- 接受云备份后，服务端从校验过的角色资料计算排名指标，战力不直接采用客户端自报分数。
  排名随低频上传更新，失败或冲突的上传不更新榜单；断网仍可本地游玩，但公共排名暂不变化。
- 开发身份/控制台测试数据与正式账号榜单隔离，开发阶段可演示榜单排序；
  正式对外开放须有稳定账号身份和道号。当前尚未接入Discord，不冒充已经解决。
- 保留现有客户端结算及基础完整性检查；服务端重新计算指标不等于证明历史过程合法，
  不承诺竞技级反作弊，不因纯数据榜恢复逐战斗服务端结算。

## 6. 首版实施记录

### 履历与保存

- `core/prototype/history.ts` 定义必填履历和基本一致性规则；在战斗、移动、制作、用物、
  采矿和交易的实际结算点记账，随角色整体保存，拒绝命令不改变原快照。
- 配方以 `recipe:配方ID` 记逐炉尝试/成功/产量，炼器与防具升炼分别以
  `assemble:成品ID`、`upgrade:成品ID` 记账。品质只取实际自制实例最高值，
  买入、发放或普通掉落不会伪造成自制。
- `gathered` 是采矿实际出矿数量，`used` 是直接使用数量，
  `absorbedMarrow` 是化悟消耗数量；制作原料消耗、买卖流转不混入直接使用。
  购入支出与售出收入独立累计，不用买卖净额覆盖。
- 新角色初始所在地与境界记初始里程碑；实际到达、战败/撤退返回可补首次到访，
  浏览、查看榜单及同地停留不算新的到访。首次清区记录完成时境界，晋升逐层记录。
- 测试控制台开放/完成区域、跳境界和传送不补对应履历，成功测试命令将
  `testAssisted` 置为真且不可回退。此后真实动作继续记录，但整份履历已标记为受测试干预，
  不把开发测试进度当成正式经历。
- 角色结构为 `neko-character-5`；内核 `neko-kernel-3`、内容 `neko-opening-2`、
  客户端保存封装 `opening-client-1` 未变。旧角色结构和缺失履历拒读，无兼容补全或迁移。
  累计数/最高值不得回退，首次记录不得更改或删除；矿点次数和产量等做基本一致性检查。

### 常态战力与四榜

- `core/prototype/combat-power.ts` 复用角色属性来源，只有估分时排除阶段援助；
  不改实战属性，临时页面“自身”栏展示当前本地常态分。
- `shared/rankings.ts` 定义公开响应，`server/client/rankings.ts` 计算四榜。
  修为先比境界，炼制先比熟练级别，同级再比累计进度；战力取当前配装、灵石取余额。
  使用精确数值比较，不转为浮点数排序，不保存历史最高战力。
- `GET /api/client/rankings/:board` 需要现有开发身份，并核对请求角色与会话一致。
  榜单只读取 `dev_sessions` 所属角色的已接受云快照，在只读一致性事务中每批读取100份，
  校验后只保留排名所需摘要；不另建榜单表、不执行数据库结构变更。
- 每次查询采用当前统一公式重算，不混排旧分；旧版/无效快照不入榜，不修改其数据。
  同指标用竞赛名次并列（如1、1、3），展示最多50条及本人名次；并列跨展示边界时
  仅以内部稳定ID决定展示顺序，不拿更新时间或ID打破并列名次。
- 本机开发榜使用由角色身份稳定生成的“试修”代号标示开发身份；界面曾另标注“开发榜 · 非正式名录”，
  2026-09-30 按用户要求清理前端内部说明后改为“璇玑阁 · 修士名录”，不再显示内部标注。
  正式账号榜不存在，生产模式仍拒绝启动；未添加正式道号设置或Discord接入。
- 响应只含代号、境界、本榜指标、收录时间及名次/本人标识，不回传位置、装备或行囊。
  上传拒绝、限流或冲突不会写入云快照，所以不改变榜单；最新本地配装须待上传后反映到云榜。
